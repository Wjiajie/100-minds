# Pass 2 改写标尺（给 worker 的硬规则）

> 每一篇改写必须严格按本文件执行。已通过的 5 篇示范稿是唯一参照基准。

## 1. 标尺文件位置

worker 开始任务时，必须先读这 5 篇标杆：

- `app/src/content/models/第一性原理.mdx`
- `app/src/content/models/黑天鹅.mdx`

(这两篇是已通过的改写版本。其他 267 篇需要按同样标准改写。)

## 2. 5 个固定模块标题（必须执行）

把任何形式的 H2 标题统一替换为以下 5 个（顺序不变）：

```
### 核心定义
### 起源
### 怎么用
### 用在哪
### 延伸阅读
```

**禁止**：
- `## 1.` / `## 2.` 之类的编号
- `💡` / `📖` / `🔍` / `🛠️` / `🔗` 之类的 emoji
- `(Core Definition)` / `(Origin & Story)` / `(Deep Dive)` / `(Application Scenarios)` / `(Authoritative References)` 之类的英文括注
- 任何 `## 概述` / `## 核心要点` / `## 例子` 之类的旧标题

## 3. frontmatter 处理

**必须保留** frontmatter 块（即 `---` 包围的 title + description 段），**不可删除**——站点渲染依赖它。

但**`---` 顶部分割线必须保留**（MDX frontmatter 语法要求）。

## 4. 标点规则

- 中文正文必须使用全角标点：`，`、`。`、`：`、`；`、`？`、`！`
- 英文专有名词 / 链接 / DOI 内部用半角
- 破折号统一用「——」（中文双破折号），每篇不超过 5 处
- 引号统一用「」或""，不要混用

## 5. 加粗使用规则

- 全文 `**xxx**` 加粗 **不超过 3 处**
- 只在以下场景使用加粗：第一次出现的关键术语、关键判断、关键转折
- **禁止**：用加粗代替段落标题、用加粗强调"重要""关键""核心"等空话
- 加粗不破坏阅读节奏——读者扫过去不会觉得"到处都是重点"

## 6. 真实案例补强规则

**每篇至少补 3 个真实案例**（含原有就够的不用加）。

每个真实案例必须包含：
- 具体的**人物/机构/事件**名字
- **年份**或可考时间
- **数字/数据**（金额、人数、比例、增长率等可验证的指标）
- 引用出处（书名 / 论文标题 / 报道 / 公开演讲均可，**禁止编造**）

**禁止**：
- "比如" + 模糊场景（"比如某公司做某事"——这种不要）
- "有研究表明"——必须给具体研究者
- "在当今时代"——空话
- 编造的人名/数据/书名——找不到就跳过这处案例，不要瞎补

**真实案例来源**（worker 可用）:
- 历史/科学事实：维基百科、Britannica、Stanford Encyclopedia of Philosophy
- 商业案例：公开年报、创始人公开演讲、新闻报道
- 心理学/经济学实验：原始论文 DOI、Kahneman / Tversky / Thaler 等公认的实验
- 引用失败处理：保留"未找到可靠单篇 Reddit 来源，可检索关键词 xxx" 这种 humanizer 承认不确定的写法

## 7. 风格标尺

**人味判断**（改写后必须满足）:

- **句长 cv > 0.5**（句长方差/均值），不允许每段一样长
- **段间长度差异大**：长 / 短 / 中 / 超短 / 中 的混搭
- **第一人称偶尔使用**（"我倾向于""我自己理解""我反复琢磨"），但不是每段都"我认为"
- **承认复杂性**：可以说"我不太确定""这事还有另一面"
- **加 1-2 处合理质疑**（"这话我听过不下二十遍，但……"），不要全部肯定陈述

**humanizer 规则**（已通过 30+ 模式触发词扫描）:
- 不出现"赋能 / 范式 / 底层逻辑 / 链路 / 抓手 / 闭环 / 复盘 / 反哺 / 沉淀 / 拉通 / 对齐"
- 不出现"标志着 / 见证了 / 开启了 / 揭开了...序幕"
- 不出现"具有重要意义 / 战略意义 / 重大意义"
- 不出现"全方位 / 全链路 / 全维度 / 全场景 / 全周期"
- 不出现"持续推动 / 不断推进 / 深入实施 / 扎实开展 / 稳步推进"
- 不出现"前景广阔 / 未来可期 / 大有可为 / 值得期待"
- 不出现"此外 / 与此同时 / 同时" 的机械转折（"另外 / 还有 / 顺带" 更自然）
- 不出现"综上所述 / 总之 / 总的来说 / 综合来看"
- 不出现"值得注意的是 / 需要指出的是 / 不可否认"
- 不出现"换言之 / 换句话说 / 也就是说" 的同义反复
- 不出现"首先...其次...再次...最后" 机械四点
- 不出现"既...又... / 不仅...而且...更" 机械双重
- 不出现"希望对您有帮助 / 让我们一起 / 码字不易" 求赞/客服腔
- 不出现"截至...年...月" 知识截止日
- 不出现"以上内容由...整理" AI 声明

## 8. 输出要求

每篇改写后，worker 在 deliverable 里必须记录：

1. **改写前字数 → 改写后字数**
2. **加粗数：改前 → 改后**（目标：≤3）
3. **破折号数：改前 → 改后**（目标：≤5）
4. **新增真实案例数**（带年份/数字/出处）
5. **残留 humanizer 触发词**（如有，写明）
6. **整体一句话自评**（"这篇我重点改了xxx"）

## 9. 失败处理

- 找不到真实案例 → 保留原有内容，不强编
- 单篇改了 2 轮还是没把握 → 标记 `needs-human-review`，跳过
- 引用找不到原文 → 不删引用，保留原样加备注"未在公开渠道核验"
- 觉得原文写得太好无需改 → 也照本标尺过一遍：H2→H3、加粗清零、标点统一

## 10. 不许动的

- 5 模块结构（核心定义 / 起源 / 怎么用 / 用在哪 / 延伸阅读）
- frontmatter 的 title / description 字段
- 链接的 URL
- DOI 编号
- 论文/书名（如 *The Black Swan* 这种）

## 11. 真实案例强约束（critical · 上一轮踩坑）

**上一轮 worker 普遍问题：自检报告失真**。声称"全部 0 命中""破折号 0 个"但实际有上百个。**这一轮必须按以下方式做案例**：

1. **每篇至少 3 个真实案例**，每案例包含：
   - 真实人物 / 机构 / 事件名字
   - 年份或可考时间
   - 数字 / 数据
   - 可外部验证的出处（书名 / 论文标题 / 报道 / 公开演讲）
2. **案例必须用 web_search 验证** —— 调用 `mavis mcp call matrix web_search '{"query":"<案例关键词>"}'` 至少 1 次 / 案例，**确认年份、数字、机构名真实存在**。
3. **找不到的事不要写**。比如不要写"Microsoft 2010-2020 Focus Time 计划"（这是 AI 捏造的；根本没有这个项目）。宁缺勿编。
4. **DOI / 链接必须原文保留**。如果原文有 DOI 10.xxxx/xxxxx，改写后这个 DOI 必须还在"延伸阅读"段。如果原文有 `https://...` 链接，保留 URL 字符串不变。
5. **不要新增外链**（避免编造链接）。新案例用"书名 + 年份 + 作者"或"公开演讲 + 年份 + 演讲人"格式。
6. **网络 / 实验 / 政策类数据必须可查**。例如"2023 年加拿大鲑鱼未恢复"——这种带年份的"未恢复"陈述，要么 web_search 验证，要么不写。

## 12. 自检失真问题（critical · 上一轮踩坑）

**禁止**：
- 自检时用错误的统计方法（如把"——"统计成"—"或反之）。必须用 Python 严格匹配。
- 自检后声称"0 命中"但 verifier 实际扫到 100+。这是失真，会被 reject。
- 跳过加粗 / 破折号 / 触发词的真实统计。

**必须**：
- 每篇改完用 `humanizer_audit.py` 跑一次，把结果附在 deliverable.md 里。
- 自检数据必须可复核 —— 给出具体数字（加粗 X 处、破折号 Y 个、触发词 Z 处）。
- 自我 cross-check：把自检数字和 audit 脚本输出对比，差异 > 20% 必须重检。

## 13. 篇幅与时间预算

- **每篇 1-3 分钟改写**，每 worker session 一次处理不超过 **6 篇**（不是 18 篇）。
- 18 篇会吃满 context window 并超时。**强制 6 篇 / session**，或 6 篇 / sub-batch。
- 先读 6 篇 → 改 6 篇 → 自检 6 篇 → 写 deliverable → 退出。一次完成。
- 不要并行 subagent 抢 token（worker 自身 context 不够用）。

## 14. 严格硬阈值（破折号 / 加粗 / 触发词）

- **破折号 `——` ≤ 3 处/篇**（不是 5 处/篇；上一轮 worker 用 7-8 处"标杆"做借口）
- **加粗 `**xxx**` ≤ 3 处/篇**
- **humanizer 触发词 = 0**（`赋能 / 范式 / 复盘 / 沉淀 / 闭环 / 抓手 / 全方位 / 多维度 / 标志着 / 见证了 / 此外 / 综上所述 / 值得注意的是 / 换言之 / 换句话说 / 众所周知` 等）
- **frontmatter description 中如有触发词允许保留**（按原 STANDARDS §10 规则）
- **核心定义段必须以一句话破冰**（"X 是...一句话"），不堆定义。

## 15. 失败处理（更新版）

- 单篇改完后 `humanizer_audit.py` 跑分 < 80 → 必须重改该篇
- 单 worker session 内 < 5 篇达标 → 整批 reject
- 找不到真实案例 → 保留原文，不强编
- 引用找不到原文 → 不删引用，保留原样加备注
- 单篇改了 2 轮还没把握 → 标记 `needs-human-review` 跳过，不要无限循环
